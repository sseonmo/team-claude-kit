# team-guardrails

> **실수를 막는 장치이지, 악의를 막는 장치가 아니다.**

훅은 명령 문자열을 보는 정적 판정기다. 변수 치환(`P=~; rm -rf $P`), 인코딩(`base64 -d | sh`),
스크립트 경유(`bash setup.sh`), 인터프리터 경유(`python -c "shutil.rmtree('/')"`)는 **전부 통과한다.**
구현을 잘하면 메워지는 구멍이 아니라 정적 판정의 원리적 한계다.

이 한계를 먼저 적는 이유는, 이걸 모르면 **막힌다고 믿으면서 안 막히는 상태**가 되기 때문이다.
그게 안 막히는 것보다 위험하다.

## 지금 하는 것 — 룰 2개

| 룰 | 무엇을 | 어떻게 |
|---|---|---|
| **D1** | `rm -rf` 대상이 프로젝트 밖 | 경로를 정규화한 뒤 `/`·홈·프로젝트 루트 자체·프로젝트 밖이면 `deny` |
| **D3** | `git push` 의 force 계열 | `--force`·`-f`·`+refspec` 을 `deny`. **`--force-with-lease` 는 통과** |

두 룰의 공통점은 **명령이 아니라 대상을 본다**는 것이다.

```
rm -rf node_modules          → 통과   (프로젝트 안)
rm -rf dist                  → 통과
rm -rf packages/a/../b/tmp   → 통과   (정규화하면 프로젝트 안)
rm -rf ~                     → 차단
rm -rf ../other              → 차단
cd /tmp && rm -rf /          → 차단   (세그먼트를 나눠 각각 본다)

git push --force-with-lease  → 통과
git push -f                  → 차단
git push origin +main        → 차단

echo "rm -rf /"              → 통과   ← 정규식 훅이 막던 대표적 오탐
git commit -m "remove rm -rf"→ 통과
```

**표기와 순서를 흡수한다.** `rm -rf` · `rm -fr` · `rm -Rf` · `rm -r -f` · `rm --recursive --force` ·
`sudo rm -rf` 는 전부 같은 판정을 받는다. 정규식 한 줄로 때우면 다음 변형에서 또 뚫린다 —
이 플러그인은 정확히 그 사고에서 나왔다.

## 지금 하지 않는 것

Detect(감사 로그)와 Contain(worktree 격리)은 **설계돼 있지만 만들지 않았다.**

Detect 는 산출물이 세션 끝의 한 줄 요약인데, 그 한 줄을 위해 전량 로깅·redact 3단계·
50MB 로테이션·역방향 집계가 따라온다. 그리고 로그 파일 자체가 새 유출 경로가 되어
그걸 막는 룰이 또 필요해진다. **요약 한 줄이 실제로 쓸모 있다고 확인된 뒤에** 짓는 게 맞다.

Contain 은 훅이 저장소를 변경(자동 stash)하는 유일한 층이라 가장 나중이어야 한다.

## `auto` 모드와의 관계 — 중복이 아니라 보완

Claude Code 의 `auto` 모드 classifier 와 겹치는 영역이 있다. 하지만 classifier 는
`auto` 에서만 돌고 모델 호출이라 비용이 든다. 나머지 모드(`default`·`plan`·`acceptEdits`·
`dontAsk`·`bypassPermissions`)에서는 아무것도 돌지 않는다.

이 훅은 **모든 모드에서 무료로, 결정론적으로** 돈다.

## 설계 원칙

**판정은 JSON 으로만 전달하고 종료 코드는 항상 0 이다.**
PreToolUse 에서 차단하는 코드는 `exit 2` 이고 `exit 1` 은 non-blocking error 라 도구가 그대로
실행된다. 이 둘을 헷갈리면 훅이 조용히 무력화되고, 사용자는 막힌다고 믿는 채로 안 막힌다.
그래서 종료 코드 규약에 아예 의존하지 않는다.

**전 구간 fail-open.** 훅이 죽든, JSON 파싱이 실패하든, 룰이 예외를 던지든 **통과시킨다.**
대가는 분명하다 — 훅을 죽이는 것만으로 모든 룰이 무력화된다. 그래도 fail-closed 로 만들면
훅 버그 하나가 세션 전체를 잠그고, 그 위험이 더 크다고 판단했다.

**deny 에는 다음 행동을 함께 준다.** 막기만 하고 길을 안 주면 에이전트는 같은 시도를 반복한다.

**판단 기준은 오탐이다.** 오탐이 잦은 훅은 사용자가 끄고, 꺼진 훅은 없는 훅과 같다.
룰을 추가할 때마다 "걸리면 안 되는 것" 테스트를 함께 늘린다.

## 다른 훅과 함께 살기

같은 `PreToolUse` 자리에 다른 훅이 있어도 안전하다 — Claude Code 는 등록된 훅을 모두 실행하고
하나라도 deny 면 deny 다. 통과할 때 **아무것도 출력하지 않는** 이유가 이것이다
(`"allow"` 를 돌려주면 다른 훅의 판정을 덮어쓴다).

차단 사유는 항상 `[guardrail D1]` 처럼 룰 ID 로 시작한다. 여러 훅이 걸려 있어도
누가 막았는지 한눈에 보인다.

**이 플러그인은 다른 훅을 수정하거나 제거하지 않는다.**

## 알려진 한계

전부 **미탐**(막아야 할 것을 놓치는 쪽)이다.

- 변수 치환·명령 치환·스크립트/인터프리터 경유는 통과한다 (위 포지션 절)
- 심볼릭 링크를 따라가지 않는다 — 경로 문자열만 정규화한다
- **프로젝트 루트가 곧 홈이면 홈 하위 보호가 성립하지 않는다.** 이 룰의 경계는 프로젝트
  루트이므로, 홈에서 세션을 열면 `~/.ssh` 도 "프로젝트 안"이 된다.
  `~` 자신과 `/` 는 이 경우에도 막힌다.
- **디렉토리를 옮긴 뒤(`cd`·`pushd`·`popd`)의 상대경로는 판정하지 않는다.**
  `cd /tmp && rm -rf junk` 도, `cd /tmp && rm -rf ..` 도 통과한다.
  **절대경로 대상(`/`·`~`·`$HOME`·프로젝트 밖 절대경로)만** 이 경우에도 막힌다
  — 아래 "`cd` 를 왜 해석하지 않는가" 참조
- **훅은 명령 문자열 하나만 본다.** Claude Code 의 Bash 도구는 호출 사이에 작업 디렉토리를
  유지하므로, 앞선 호출에서 옮겨둔 위치는 훅이 알 수 없다. 이 경우 상대경로 판정이
  어긋날 수 있다 — 위 규칙이 "옮겼으면 접는다"인 이유이기도 하다
- `git -C <경로> push` 는 잡지만, 값을 받는 다른 git 전역 옵션 조합은 빗나갈 수 있다
- `sudo rm -rf` 는 잡지만 `sudo -u root rm -rf` 는 빗나간다

오탐(정상 작업을 막는 것)은 현재 알려진 것이 없다.

## `cd` 를 왜 해석하지 않는가

`v0.1.1`~`v0.1.7` 은 `cd` 의 목적지를 추적했다. **일곱 번 릴리스하는 동안 오탐이 일곱 번 났고,
그중 여섯이 여기서 나왔다.** 매번 테스트를 전부 통과한 상태로 나갔다.

| | 막아버린 정상 명령 |
|---|---|
| `v0.1.0` | `rm -rf dist > /dev/null 2>&1` — 리다이렉션 대상을 삭제 대상으로 오인 |
| `v0.1.1` | `(cd /tmp && tar xzf a.tgz) && rm -rf dist` — 서브셸의 `cd` 가 밖으로 샘 |
| `v0.1.2` | `(cd ../x && npm i) && (rm -rf dist)` — 형제 서브셸이 깊이로 구분 안 됨 |
| `v0.1.4` | `cd - && (rm -rf ../x)` — "모른다"가 기본값으로 되살아남 |
| `v0.1.5` | `if …; then\n cd /tmp\nfi\nrm -rf node_modules` — 여러 줄 조건문 |
| `v0.1.6` | `cleanup() { cd /tmp; }\nrm -rf node_modules` — 함수 정의를 즉시 실행으로 오인 |
| `v0.1.7` | `function deploy {\n cd ../x\n}\n…` — ksh 스타일 함수 |

원인은 하나다. **셸에서 `cd` 가 실제로 실행되는지는 문자열만 보고 알 수 없다.**

```bash
cd /tmp && rm -rf junk          # 실행됨
(cd /tmp) && rm -rf junk        # 서브셸 → 밖으로 안 나옴
cd /tmp | cat; rm -rf junk      # 파이프 → 서브셸
if [ -d x ]; then cd /tmp; fi   # 조건 → 실행될 수도, 안 될 수도
deploy() { cd /tmp; }           # 함수 정의 → 지금은 실행 안 됨
{ cd /tmp; }                    # 즉시 실행 그룹 → 실행됨   ← 위와 글자가 거의 같다
```

`v0.2.0` 은 목적지 추적을 들어냈다. 대신 **디렉토리를 옮겼다는 사실만** 쓴다 —
그 뒤의 상대경로는 "어디인지 모른다"로 두고 판정하지 않는다.
`cd` 만 세면 `pushd`·`popd` 에서 같은 오탐이 나므로 셋을 함께 센다(`v0.2.1`).

`cd` 를 통째로 무시하는 것도 답이 아니다. `cd packages/app && rm -rf ../shared` 의 `..` 은
옮긴 위치 기준이라, 프로젝트 루트로 풀면 정상 명령이 "프로젝트 밖"이 된다.
**모른다고 두는 자리가 두 오탐을 동시에 피하는 유일한 지점이다.**

잃은 것은 **디렉토리를 옮긴 뒤 상대경로로 지우는** 형태의 미탐이다
(`cd /tmp && rm -rf junk`, `cd /tmp && rm -rf ..`).
`rm -rf /`·`rm -rf ~`·`rm -rf $HOME` 같은 절대경로 대상은 그대로 막히고,
옮기지 않았다면 `rm -rf ..`·`rm -rf .` 도 그대로 막힌다.

> **덜 아는 편이 더 안전할 때가 있다.** 모르는 것을 안다고 단정하면 오탐이 되고,
> 오탐이 잦은 훅은 꺼지고, 꺼진 훅은 아무것도 막지 못한다.

## 테스트

```
npm test        # node --test test/*.test.mjs — 의존성 없음
```

99개 케이스가 세 종류로 나뉜다: **걸려야 하는 것** · **걸리면 안 되는 것** ·
**통과가 정상인 우회**. 세 번째가 핵심이다 — 나중에 누군가 "이것도 막자"며 변수 치환이나
`cd` 해석을 넣으려 할 때, 테스트가 설계 의도를 대신 말해준다.

`test/shell-syntax-sweep.test.mjs` 는 셸 문법을 **구문 종류로 나눠** 한 표에 세워 둔 것이다
(명령 치환·리다이렉션 변형·파이프/백그라운드·경로 정규화·줄바꿈·인용부호·서브셸·
명령 접두어·`cd`·조건문/반복문/함수 정의·여러 줄 스크립트). 파서를 건드리면 이 표가 먼저 깨진다.

이 표는 `v0.1.4` 에서 셸 문법을 일제 점검하다 나왔다. 어긋난 13건이 **전부
"명령 이름 앞에 붙는 것들"** 한 부류였고, 룰마다 흩어져 있던 처리를 `stripCommandPrefixes`
하나로 모았다. **부류를 찾아 한 곳에서 막는 편이, 새어나온 형태를 하나씩 붙이는 것보다 낫다.**

그런데 그 뒤로도 축이 계속 늘었다. `v0.1.5`·`v0.1.6` 이 각각 축을 더했고, 매번 **직전 릴리스의
회귀가 정확히 새로 추가된 그 축에서** 나왔다. 표에 축이 없어 통과했던 것이다.
**표는 자기가 가진 축까지만 지킨다.** 축이 계속 늘어난다는 것 자체가 신호였고,
`v0.2.0` 에서 축을 늘리는 대신 그 축들이 필요했던 기능(`cd` 목적지 추적)을 들어냈다.

진입점은 실제 프로세스로 띄워 stdin JSON 을 먹여 검증한다.
**인라인 훅이 못 하던 게 정확히 이 검증이고, 그래서 버그가 산 채로 남아 있었다.**
