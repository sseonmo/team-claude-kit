# handoff — /clear 를 건너뛰는 작업 인계

자동 로드되는 `MEMORY.md` 에 ⏸ 포인터를 심어, `/clear` 후 새 세션이 스스로 인계를 발견하게 한다.

## 원칙

1. **`/clear` 는 내가 실행할 수 없다.** "클리어까지 해줄게"라고 말하지 마라.
2. **요약이 아니라 재개 지시서를 쓴다.** 다음 세션이 첫 명령을 바로 칠 수 있어야 한다.
3. **재개하면 보고만 하고 멈추지 않는다.** 다음 단계 1에 바로 착수한다(❓ 결정 대기가 있으면 그것부터 묻는다).
4. **메모리는 과거의 관찰이다.** 기록이 현재 repo 와 어긋나면 현실을 믿고 그 사실을 알린다.
5. **커밋·푸시는 하지 않는다.** 프로젝트 CLAUDE.md 규칙이 이 스킬보다 우선한다.

## 0. 상태 수집 (항상 먼저)

```bash
STATE=$(find "$HOME/.claude/plugins/cache" \
  -path '*team-handoff/*/skills/handoff/scripts/state.sh' 2>/dev/null | sort -V | tail -1)
[ -f "$STATE" ] || STATE="$HOME/.claude/skills/handoff/scripts/state.sh"
if grep -qs 'HANDOFF_STATE=' "$STATE"; then bash "$STATE"; else echo "HANDOFF_STATE_NOT_FOUND"; fi
```

- `HANDOFF_STATE_NOT_FOUND` → 설치가 잘못됐다. 알리고 중단한다.
- `CONFIRM_DIR=yes` → `MEMORY_DIR` 에 쓰거나 만들기 **전에** 그 경로가 맞는지 사용자에게 확인한다.
  `CONFIRM_DIR` 줄이 아예 없으면 구버전 스크립트다 — `yes` 로 간주한다.
- `CWD_MOVED=yes` → git 상태는 `GIT_ROOT` 저장소의 것이다. 본문에 어느 repo 인지 밝힌다.

`HANDOFF_STATE` 로 모드를 정한다. 사용자가 "저장해"/"재개해"라고 하면 그 말이 우선한다.

| 값 | 모드 |
|---|---|
| `none` | 저장 |
| `pending` | 재개 |
| `orphan` | 파일은 있는데 포인터가 없다(저장이 조용히 실패). 알리고, 아직 유효하면 포인터를 복구해 재개, 끝난 작업이면 정리 |
| `ghost` | 인덱스에만 ⏸ 줄이 남았다. 지우고 저장 |

그 밖의 인자는 다음 세션에 대한 지시다 — 저장 모드에서는 "다음 단계"를 그 목표에 맞추고,
재개 모드에서는 파일의 "다음 단계"보다 우선한다.

## A. 저장 모드

`$MEMORY_DIR/handoff-active.md` 를 쓴다(있으면 덮어쓴다). `<BRANCH>` 처럼 `state.sh` 출력 키 이름인 자리는 그 값을 그대로 옮긴다.

```markdown
---
name: handoff-active
description: ⏸ 진행 중 작업 인계 — <한 줄 주제>. /handoff 로 재개
metadata:
  type: project
---

# ⏸ <한 줄 주제>

**재개 방법**: `/handoff` · **저장 시각**: <YYYY-MM-DD HH:MM> · **브랜치**: <BRANCH> · **HEAD**: <HEAD_SHA> <HEAD_MSG>

## 지금 무엇을 하는 중인가
<왜 이 작업을 하는지 2~3줄>

## 다음 단계 (여기부터)
1. <실행할 명령을 백틱으로 그대로. stash 에 작업이 있으면 복원 명령이 1번이다>
2. …

## 🚨 하지 말 것
<되돌리기 어려운 것, 재실행하면 안 되는 명령, 건드리면 안 되는 파일>

## 확인된 사실 (다시 조사하지 말 것)
<실측으로 확정한 것만. 통과·미통과·미확인을 구분하고, "통과"는 검증 명령과 출력을 함께 적을 때만 쓴다>

## ❓ 사용자 결정 대기
<없으면 "없음">

## 상태
- 미커밋: <DIRTY_COUNT>개 — <MODIFIED·UNTRACKED 목록. 디렉토리는 `(N files)` 까지>
- stash: <STASH_COUNT> · 추가 워크트리: <WORKTREE_OTHERS>
- 환경 전제: <서버·DB 등 + 되살리는 명령. 비밀값은 `REDACTED` 나 환경변수 이름으로>

## 재개 시 로드할 스킬
<이 작업에 쓰던 스킬. 없으면 "없음">

## 참조
- 계획/설계: <경로 — 내용은 옮겨 적지 않는다>
- 관련 메모리: [[…]]
```

**`MEMORY.md` 최상단**에 포인터 한 줄(있으면 교체). 본문은 쓰지 않는다:

```markdown
- [⏸ 진행 중 인계 — <한 줄 주제>](handoff-active.md) — `/handoff` 로 재개. 다음: <첫 동작 요약>
```

쓰기 전에 확인한다:
- API 키·비밀번호·토큰·개인정보가 없다 — 이 파일은 매 세션 읽힌다
- 계획서·스펙·커밋 내용을 복사하지 않고 경로로만 참조했다
- 지속 가치가 있는 교훈은 별도 메모리에 남겼다(새 파일보다 기존 파일 갱신 우선)

**검증** — 0단계 블록의 `bash "$STATE"` 를 `bash "$STATE" --verify` 로 바꿔 실행한다(셸 변수는 호출 사이에 유지되지 않으니 세 줄 모두).
`VERIFY_RESULT=pass` 가 나오기 전에는 "저장했습니다"라고 말하지 마라. `fail` 이면 고치고 다시 실행한다.

통과하면 **정확히 이렇게** 안내한다:

```
저장했습니다. 이제 이렇게 하세요.

  1) /clear
  2) /handoff

`/clear` 는 제가 실행할 수 없어 직접 입력하셔야 합니다. 그 다음은 제가 이어서 진행합니다.
```

## B. 재개 모드

1. **읽는다** — `handoff-active.md` 와 "참조"의 문서. "재개 시 로드할 스킬"은 착수 전에 호출한다.
2. **대조한다** — `BRANCH`·`HEAD_SHA`·`DIRTY_COUNT` 가 파일과 다르면 먼저 보고한다.
   언급된 파일·함수·플래그는 존재를 확인한 뒤 쓴다. `HANDOFF_AGE_DAYS` 가 크면 이미 해소된 작업인지부터 본다.
3. **환경을 되살린다** — "환경 전제"를 점검하고 죽어 있으면 띄운다.
4. **착수한다** — "다음 단계 1"부터 실행한다. ❓ 결정 대기가 있으면 그것부터 묻는다.
5. **갱신한다** — 진행하면서 "다음 단계"를 실제 위치로 고친다. 다시 `/handoff` 하면 덮어쓴다.
6. **끝나면 정리한다** — `handoff-active.md` 삭제, `MEMORY.md` 의 ⏸ 줄 제거.
   결과·교훈은 기존 메모리 갱신을 우선하고, 이번 작업으로 틀리게 된 메모리는 고치거나 지운다.

첫 응답은 3줄:

```
인계 확인: <한 줄 주제>
상태 대조: <일치 / 어긋난 점>
다음: <첫 동작> → 바로 진행합니다.
```
