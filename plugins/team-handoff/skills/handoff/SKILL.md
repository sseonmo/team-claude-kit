# handoff — /clear 를 건너뛰는 작업 인계

## 이 스킬이 존재하는 이유

`/clear` 로 컨텍스트를 비우면 다음 세션은 **아무것도 모른다.** 그래서 매번 "클리어 후 뭐라고 말해야 하죠?"
가 반복된다. 이 스킬은 그 질문 자체를 없앤다 — **자동 로드되는 `MEMORY.md` 에 대기 표시를 심어**
새 세션이 스스로 "인계받을 작업이 있다"를 알게 만든다.

## 절대 원칙

1. **`/clear` 는 내가 실행할 수 없다.** "클리어까지 해줄게"라고 말하지 마라 — 거짓이 된다.
   사용자가 하는 수동 단계는 **`/clear` 한 번뿐**이고, 나머지는 전부 이 스킬이 한다.
2. **저장 모드는 "요약"이 아니라 "재개 지시서"를 쓴다.** 다음 세션이 **첫 명령을 바로 칠 수 있어야** 한다.
   "무엇을 했는지"보다 **"다음에 무엇을 하는지"** 가 중요하다.
3. **재개 모드는 보고만 하고 멈추지 않는다.** 상태를 확인했으면 **다음 단계의 첫 작업에 착수**한다.
   (단, 저장 시 "사용자 결정 대기"로 표시된 항목이 있으면 거기서 멈추고 물어본다.)
4. **메모리는 과거의 관찰이다.** 재개 시 파일이 말하는 것을 **현재 repo·환경과 대조**하고,
   어긋나면 파일이 아니라 현실을 믿고 그 사실을 사용자에게 알린다.
   이는 `handoff-active.md` 하나가 아니라 **이번 작업이 건드린 영역의 기존 메모리 전부**에 적용된다.
5. **커밋·푸시는 하지 않는다**(사용자 지시 전용). handoff 는 기록이지 커밋이 아니다.
6. **인덱스에는 예산이 있다.** `MEMORY.md` 는 **매 세션 자동 로드되는 유일한 파일**이다.
   handoff 사이클마다 ⏸ 줄을 지우고 교훈 줄을 더하면 항목은 **순증만 한다** — 그러면
   이 스킬을 많이 쓴 프로젝트일수록 세션 시작 비용이 커진다. **더하기 전에 갱신을 먼저 본다.**

## 실행 절차

### 0. 모드 판정 (항상 먼저)

스크립트 경로는 설치 형태(플러그인 / 개인 스킬)에 따라 다르므로 먼저 찾는다:

```bash
STATE=$(find "$HOME/.claude/plugins/cache" "$HOME/.claude/skills" \
  -path '*handoff/scripts/state.sh' 2>/dev/null | head -1)
bash "$STATE"
```

`$HOME/.claude/plugins` 전체가 아니라 **`cache` 만** 본다. 마켓플레이스를 로컬에 클론해 두면
`plugins/marketplaces/…` 아래에도 같은 파일이 있어 `find` 가 둘을 찾는데, 그쪽은 **배포 소스지
설치본이 아니다.** `find` 의 출력 순서는 파일시스템 순회 순서라 보장되지 않으므로(리눅스 ext4 는
해시 순서), 마켓플레이스만 pull 하고 재설치하지 않은 상태에서 그쪽이 먼저 잡히면
**설치하지 않은 버전의 스크립트가 실행된다.** 설치본은 user·project 스코프 모두 `cache` 아래에 놓인다.

`STATE` 가 비면 스킬이 제대로 설치되지 않은 것이다 — 사용자에게 알리고 중단한다.

- `HANDOFF_PENDING=no` → **저장 모드**
- `HANDOFF_PENDING=yes` → **재개 모드**
- 사용자가 "저장해"/"재개해"를 명시하면 그 말을 따른다(판정보다 우선).
- `MEMORY_EXISTS=no` 면 그 디렉토리를 만들고 진행한다(`MEMORY.md` 도 없으면 새로 만든다).
- `MEMORY_DIR_FALLBACK=yes` 면 cwd 슬러그가 아니라 **basename 추정으로 찾은 경로**다.
  워크트리·심링크에서 정상 동작이지만, **쓰기 전에 그 경로가 맞는지 사용자에게 확인한다** —
  틀리면 남의 프로젝트 메모리에 인계를 쓰게 된다.

### A. 저장 모드

`state.sh` 출력으로 기계적 사실은 이미 확보됐다. **대화 맥락에서만 알 수 있는 것**을 채우는 게 본 작업이다.

`$MEMORY_DIR/handoff-active.md` 를 아래 형식으로 쓴다(있으면 덮어쓴다):

```markdown
---
name: handoff-active
description: ⏸ 진행 중 작업 인계 — <한 줄 주제>. /handoff 로 재개
metadata:
  type: project
---

# ⏸ <한 줄 주제>

**재개 방법**: `/handoff` (이 파일을 읽고 아래 "다음 단계"부터 착수)
**저장 시각**: <YYYY-MM-DD HH:MM> · **브랜치**: <BRANCH> · **HEAD**: <SHA> <메시지>

## 지금 무엇을 하는 중인가
<왜 이 작업을 하는지 2~3줄. 배경이 없으면 다음 세션이 엉뚱한 판단을 한다>

## 다음 단계 (여기부터)
1. <첫 동작 — **실행할 명령을 그대로** 적는다>
2. <그 다음>
3. …

## 🚨 하지 말 것
<방향을 거꾸로 잡으면 파괴적인 것, 재실행하면 안 되는 명령, 건드리면 안 되는 파일>

## 확인된 사실 (다시 조사하지 말 것)
<이미 실측으로 확정한 것만. 추측은 넣지 않는다>

## ❓ 사용자 결정 대기
<있으면 적는다. 없으면 "없음". 여기 항목이 있으면 재개 모드는 그것부터 묻는다>

## 상태
- 미커밋: <N>개 — <주요 파일 나열>
- stash: <N> · worktree: <N>
- 환경 전제: <서버·DB·브라우저 등 + 되살리는 명령>

## 참조
- 계획/설계: <경로>
- 관련 메모리: [[…]] [[…]]
```

그리고 **`MEMORY.md` 최상단**에 포인터 한 줄을 넣는다(이미 있으면 교체):

```markdown
- [⏸ 진행 중 인계 — <한 줄 주제>](handoff-active.md) — `/handoff` 로 재개. 다음: <첫 동작 요약>
```

**인덱스 한 줄로 "이 파일을 열어볼지" 판단할 수 있으면 충분하다. 그 이상은 본문이다.**
줄이 길어졌다면 요약을 압축할 게 아니라 **본문으로 내려야 할 내용이 인덱스에 올라온 것**이다.

**저장 모드 체크리스트**
- [ ] "다음 단계 1"이 **명령 한 줄**로 적혀 있는가(모호한 서술 금지)
- [ ] 파괴적 위험이 있으면 "하지 말 것"에 있는가
- [ ] 미커밋 파일이 빠짐없이 적혔는가(`state.sh` 출력과 대조)
- [ ] 지속 가치가 있는 지식은 **별도 메모리 파일**로도 남겼는가
      (handoff 는 작업이 끝나면 사라지는 임시물이다 — 교훈·함정은 별도 파일이 SSOT)
      → 새 파일을 만들기 전에 **기존 파일에 갱신할 수 있는지 먼저 본다**(원칙 6)
- [ ] `MEMORY.md` 포인터를 넣었는가
- [ ] `MEMORY_LINES` 가 임계를 넘었으면 **정리를 제안했는가**(아래 "인덱스 예산")

마지막에 **정확히 이렇게** 안내한다(길게 설명하지 말 것):

```
저장했습니다. 이제 이렇게 하세요.

  1) /clear
  2) /handoff

`/clear` 는 제가 실행할 수 없어 직접 입력하셔야 합니다. 그 다음은 제가 이어서 진행합니다.
```

### B. 재개 모드

1. **읽는다** — `handoff-active.md` + 거기 "참조"에 적힌 계획서·관련 메모리.
2. **대조한다**(원칙 4) — `state.sh` 의 브랜치·HEAD·미커밋 수가 파일과 같은가.
   다르면 **그 차이를 먼저 사용자에게 보고**한다(다른 세션이 작업했거나 커밋됐을 수 있다).
   파일이 특정 파일·함수·플래그를 언급하면 **존재를 확인**한 뒤 쓴다.
3. **환경을 되살린다** — "환경 전제"에 적힌 것들을 점검하고 죽어 있으면 띄운다.
4. **착수한다** — "다음 단계 1"부터 실제로 실행한다.
   단 "❓ 사용자 결정 대기"에 항목이 있으면 **그것부터 묻고** 답을 받은 뒤 진행한다.
5. **파일을 갱신한다** — 재개했음을 표시(`resumedAt`)하고, 진행하면서 "다음 단계"를 실제 상태에 맞게 고친다.
6. **작업이 끝나면 정리한다** — `handoff-active.md` 삭제 + `MEMORY.md` 의 ⏸ 줄 제거.
   그리고 그 작업의 결과·교훈을 **정식 메모리 파일**로 남긴다(handoff 파일에 방치하지 말 것).
   **단, 파일을 새로 만들기 전에 이 순서를 지킨다**(원칙 6 — 인덱스는 순증하면 안 된다):

   1. **갱신할 기존 파일이 있는가** — 같은 주제를 다루는 파일이 있으면 그 파일을 고친다.
      새 파일을 만들면 인덱스가 한 줄 늘지만, 갱신하면 늘지 않는다. **갱신이 기본이고 신설이 예외다**
   2. **이번 작업으로 틀린 게 된 메모리가 있는가** — 이번에 건드린 영역의 기존 메모리를 확인한다(원칙 4).
      파일이 언급하는 함수·플래그·경로가 사라졌거나 결론이 뒤집혔으면 **갱신하거나 삭제한다.**
      "그때는 맞았다"는 남겨둘 이유가 되지 않는다 — 인덱스에 있는 한 매 세션 로드된다
   3. **그래도 새 파일이 필요하면** 만들고 인덱스에 한 줄 추가한다

   이 세 단계를 건너뛰면 인덱스는 사이클마다 한 줄씩 자란다.
   **정리는 이 스킬에서 항목이 줄어드는 유일한 지점이다.**

**재개 모드 첫 응답 형식** — 3줄을 넘기지 마라. 사용자는 요약이 아니라 진행을 원한다.

```
인계 확인: <한 줄 주제>
상태 대조: <일치 / 어긋난 점>
다음: <첫 동작> → 바로 진행합니다.
```

## 여러 번 클리어하며 이어갈 때

저장 모드는 항상 덮어쓰므로 몇 번을 반복해도 파일은 하나다. 재개 → 조금 진행 → 다시 `/handoff` → `/clear`
사이클이 정상 사용법이다. 다만 **매 사이클마다 "다음 단계"를 실제 진행 위치로 갱신**해야
같은 지점을 반복하지 않는다.

## 인덱스 예산

`MEMORY.md` 는 **매 세션 자동 로드되는 유일한 파일**이다. 여기 있는 모든 줄은 앞으로의 모든 세션이
지불하는 고정 비용이므로, 인덱스는 커지지 않게 관리해야 하는 대상이지 쌓이는 대로 두는 로그가 아니다.

**임계는 `MEMORY_LINES` 15개 하나다.** 넘으면 저장 모드 마지막에 정리를 제안한다.
`MEMORY_BYTES` 와 `MEMORY_LONGEST_CHARS` 도 `state.sh` 가 찍지만 임계를 걸지 않는다 —
둘 다 언어에 따라 3배까지 차이나서(한글 1자 3바이트) 어떤 팀원에게는 영영 발동하지 않기 때문이다.
사람이 보고 판단할 참고값으로만 쓴다.

**정리 제안 절차** — 임계를 넘었을 때만, 저장 모드 마지막에 한 번:

1. `state.sh` 의 `STALE_30D` 목록(30일 이상 손대지 않은 파일)을 그대로 보여준다
2. 각 항목에 대해 셋 중 하나를 **사용자에게 묻는다** — 유지 / 다른 항목과 병합 / 삭제
3. 답을 받아 실행하고, 인덱스 줄도 함께 정리한다

**임의로 지우지 마라.** 오래된 것과 틀린 것은 다르다 — 반년 전에 쓴 함정이 여전히 유효할 수 있다.
스킬이 하는 일은 **후보를 실측해 제시하는 것**까지이고, 판단은 사용자의 것이다.

> **임계는 조기 경보용이지 상한이 아니다.** 15줄에서 걸린다고 인덱스가 망가진 것은 아니다 —
> **자라는 중일 때 잡으려고** 낮게 잡은 값이다. 이미 커진 뒤에는 정리 비용이 훨씬 크다.
> 이 값은 소규모 표본에서 고른 것이므로 **조정해도 된다.** 정리 제안이 잦아 성가시면 올리고,
> 손대기 전에 이미 커져 있으면 내려라.

## 함정

- **`MEMORY.md` 에 handoff 본문을 쓰지 마라** — 인덱스는 포인터, 본문은 별도 파일.
  형식상 한 줄이어도 문단 하나를 밀어 넣으면 본문을 쓴 것이다.
- **교훈 파일을 습관적으로 신설하지 마라** — 새 파일 하나는 인덱스 한 줄이고, 인덱스 한 줄은 영구 비용이다.
  기존 파일에 날짜와 함께 덧붙이는 쪽이 대개 낫다(원칙 6, 재개 모드 6단계).
- **저장 모드에서 "다 했다"고 쓰지 마라** — 검증 안 된 것을 완료로 적으면 다음 세션이 그걸 믿고 넘어간다.
  통과·미통과·미확인을 구분해 적는다. 특히 "검증 통과"는 **검증 명령과 그 출력**을 함께 적지 않으면 쓰지 마라.
- **워크트리·stash 를 남긴 채 클리어하면 다음 세션이 그 사실을 모른다** — `state.sh` 가 세는 이유다.
  stash 에 작업이 갇혀 있으면 "하지 말 것"이 아니라 **"다음 단계 1"에 복원 명령**을 적어라.
- **프로젝트 CLAUDE.md 의 규칙이 이 스킬보다 우선한다**(커밋 금지·계획 승인 등).
