# handoff — /clear 를 건너뛰는 작업 인계

자동 로드되는 `MEMORY.md` 에 ⏸ 포인터를 심어, `/clear` 후 새 세션이 스스로 인계를 발견하게 한다.

## 원칙

1. **`/clear` 는 내가 실행할 수 없다.** "클리어까지 해줄게"라고 말하지 마라.
2. **요약이 아니라 재개 지시서를 쓴다.** 다음 세션이 첫 동작을 바로 할 수 있어야 한다.
3. **재개하면 보고하고 바로 착수한다.** ❓ 결정 대기가 있으면 그것부터 묻는다.
4. **메모리는 과거의 관찰이다.** 기록이 현재 repo 와 어긋나면 현실을 믿고 알린다.
5. **커밋·푸시는 하지 않는다.** 프로젝트 CLAUDE.md 규칙이 이 스킬보다 우선한다.
6. **재개 인자는 지시이지 앞 세션 결정의 승인이 아니다.** "그대로 진행해줘"처럼 앞 세션 초안·계획의
   승인으로 읽히면, 무엇을 승인으로 받는지 보고에 밝히고 착수 전에 한 번 확인한다.

## 0. 상태 수집 (항상 먼저)

`<BASE_DIR>` 에는 이 스킬을 불러온 메시지 첫 줄 `Base directory for this skill: …` 의 경로를 그대로 넣는다.
`--verify`·`--consume` 도 이 블록의 마지막 `bash "$STATE"` 뒤에 플래그만 붙여 블록째 실행한다(셸 변수는 호출 사이에 유지되지 않는다).

```bash
STATE="<BASE_DIR>/scripts/state.sh"
[ -f "$STATE" ] || STATE=$(find "$HOME/.claude/plugins/cache" \
  -path '*team-handoff/*/skills/handoff/scripts/state.sh' 2>/dev/null | sort -V | tail -1)
[ -f "$STATE" ] || STATE="$HOME/.claude/skills/handoff/scripts/state.sh"
if grep -qs 'HANDOFF_STATE=' "$STATE"; then bash "$STATE"; else echo "HANDOFF_STATE_NOT_FOUND"; fi
```

- `HANDOFF_STATE_NOT_FOUND` → 설치가 잘못됐다. 알리고 중단한다.
- `CONFIRM_DIR=yes` → `MEMORY_DIR` 에 쓰기 **전에** 그 경로가 맞는지 사용자에게 확인한다.
- `CWD_MOVED=yes` → git 상태는 `GIT_ROOT` 저장소의 것이다. 본문에 어느 repo 인지 밝힌다.

`HANDOFF_STATE` 로 모드를 정한다. 사용자가 "저장해"/"재개해"라고 하면 그 말이 우선한다.

| 값 | 모드 |
|---|---|
| `none` | 저장 |
| `pending` | 재개 |
| `orphan` | 파일만 있고 포인터가 없다. 알리고, 유효하면 재개 · 끝난 작업이면 `--consume` 으로 정리 |
| `ghost` | 포인터만 남았다. `--consume` 으로 지우고 저장 |

그 밖의 인자는 다음 세션에 대한 지시다 — 저장 모드에서는 "다음 단계"를 그 목표에 맞추고,
재개 모드에서는 파일의 "다음 단계"보다 우선한다.

## A. 저장 모드

**덮어쓰기 전에** — `HANDOFF_CONTENT` 가 출력됐는데(`pending`·`orphan`) 이번 세션이 이어받은 것이 아니고
주제도 다르면, 쓰기 전에 "재개되지 않은 인계(<주제>)가 있습니다. 덮어쓸까요?" 라고 묻는다.

`$MEMORY_DIR/handoff-active.md` 를 쓴다(있으면 덮어쓴다). `<BRANCH>` 처럼 `state.sh` 출력 키인 자리는 값을 그대로 옮긴다.

```markdown
---
name: handoff-active
description: ⏸ 진행 중 작업 인계 — <한 줄 주제>. /handoff 로 재개
metadata:
  type: project
---

# ⏸ <한 줄 주제>

**재개 방법**: `/handoff` · **저장 시각**: <YYYY-MM-DD HH:MM> · **브랜치**: <BRANCH> · **HEAD**: <HEAD_SHA> <HEAD_MSG>

## 지금 무엇을 하는 중인가
<왜 이 작업을 하는지 2~3줄>

2. …

<되돌리기 어려운 것, 재실행하면 안 되는 명령, 건드리면 안 되는 파일>

<없으면 "없음">

```

API 키·비밀번호·토큰·개인정보는 넣지 않는다 — 이 파일은 다음 세션에 그대로 읽힌다.
`MEMORY.md` 는 **직접 고치지 않는다** — 다음 `--verify` 가 포인터 줄을 넣는다.

**검증** — Write 직후 0단계 블록을 `bash "$STATE" --verify` 로 실행한다(작업 저장소에서. 메모리 폴더로 `cd` 하지 않는다).
`VERIFY_RESULT=pass` 전에는 "저장했습니다"라고 말하지 마라. `fail` 이면 FAIL 줄대로 고치고 다시 실행한다
(포인터는 통과할 때만 들어가므로, 고치지 않고 멈추면 인계가 발견되지 않는다).
`VERIFY_FRESH=FAIL` 은 이번 쓰기가 실패해 이전 파일이 남았다는 뜻이다 — 쓰기 오류부터 확인한다.

통과하면 **정확히 이렇게** 안내한다:

```
저장했습니다. 이제 이렇게 하세요.

  1) /clear
  2) /handoff

`/clear` 는 제가 실행할 수 없어 직접 입력하셔야 합니다. 그 다음은 제가 이어서 진행합니다.
```

## B. 재개 모드

인계 본문은 0단계 출력의 `HANDOFF_CONTENT` 에 이미 있다 — 따로 Read 하지 않는다.

1. **소비한다 (생략 금지)** — 다른 어떤 도구보다 먼저 `bash "$STATE" --consume` → `CONSUME_RESULT=ok` 확인.
   남겨 두면 다른 세션이 같은 인계를 또 이어받는다(실제로 일어났다). 내용은 이미 이 세션에 있다.
2. **보고한다** — 조사·참조 문서·스킬 로드보다 **먼저** 아래 3줄을 출력한다.
3. **대조한다** — `BRANCH`·`HEAD_SHA`·`DIRTY_COUNT` 가 파일과 다르면 먼저 알린다. `HANDOFF_AGE_DAYS` 가 크면
   이미 해소된 작업인지부터 본다. 언급된 파일·함수는 존재를 확인한 뒤 쓴다. "참조"·"재개 시 로드할 스킬"은 여기서 읽고 호출한다.
4. **착수한다** — "환경 전제"가 죽어 있으면 띄우고, "다음 단계 1"부터 실행한다(❓ 가 있으면 그것부터 묻는다).
5. 다시 클리어해야 하면 `/handoff` 로 새로 저장한다(파일이 없으므로 저장 모드가 된다).
   작업이 끝나면 결과·교훈은 기존 메모리 갱신을 신설보다 우선하고, 틀리게 된 메모리는 고치거나 지운다.

```
인계 확인: <한 줄 주제> (소비: 삭제함)
상태 대조: <일치 / 어긋난 점>
다음: <첫 동작> → 바로 진행합니다.   (인자가 승인으로 읽히면: "승인으로 받을 것: <이름> — 맞나요?")
```
