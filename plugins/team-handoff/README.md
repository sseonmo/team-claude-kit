# team-handoff

`/clear` 를 건너뛰는 작업 인계 스킬.

## 문제

`/clear` 로 컨텍스트를 비우면 다음 세션은 아무것도 모른다. 그래서 매번 같은 질문이 반복된다 —
*"클리어 후에 뭐라고 말해야 하죠?"*

## 해결

**자동 로드되는 `MEMORY.md` 에 대기 포인터를 심는다.** 새 세션은 시작할 때 그 파일을 항상 읽으므로,
거기 `⏸ 진행 중 인계` 한 줄이 있으면 **스스로 인계받을 작업이 있다는 것을 안다.**

사용자가 외울 문구도 없다. 저장할 때도 재개할 때도 **`/handoff` 한 마디**면 되고,
스킬이 인계 파일과 `MEMORY.md` 포인터를 함께 보고(`HANDOFF_STATE`) 모드를 판정한다.

## 사용법

```
작업 중 → /handoff        (저장 모드: 재개 지시서 작성 + 인덱스 포인터 삽입)
        → /clear          (⚠️ 이 한 번만 사용자가 직접 입력한다)
        → /handoff        (재개 모드: 읽고 → 현실과 대조 → 바로 착수)
```

`/clear` 는 CLI 동작이라 스킬이 실행할 수 없다. 그 한 번을 제외한 나머지는 전부 스킬이 한다.

## 무엇을 저장하나

`state.sh` 가 기계적 사실을 수집하고(브랜치·HEAD·미커밋·stash·worktree·인계 상태),
스킬은 **대화 맥락에서만 알 수 있는 것**을 채운다.

| 섹션 | 내용 |
|---|---|
| 지금 무엇을 하는 중인가 | 배경. 없으면 다음 세션이 엉뚱한 판단을 한다 |
| 다음 단계 | **실행할 명령을 그대로** 적는다. 요약이 아니라 지시서다 |
| 🚨 하지 말 것 | 되돌리기 어려운 것, 재실행하면 안 되는 명령 |
| 확인된 사실 | 실측으로 확정한 것만. 추측은 넣지 않는다 |
| ❓ 사용자 결정 대기 | 여기 항목이 있으면 재개 모드가 **그것부터 묻고** 멈춘다 |
| 상태 · 참조 | 미커밋·stash·환경 전제 · 계획서·관련 메모리 링크 (내용 복사 없이 경로만, 비밀값은 가림) |
| 재개 시 로드할 스킬 | 앞 세션이 쓰던 스킬. 재개 모드가 착수 전에 호출한다 |

## 설계 원칙

- **재개 모드는 보고만 하고 멈추지 않는다.** 첫 응답 3줄로 대조 결과를 알리고 바로 착수한다
- **메모리는 과거의 관찰이다.** 기록과 현재 repo 가 어긋나면 **현실을 믿고** 그 사실을 보고한다.
  이는 handoff 파일 하나가 아니라 이번 작업이 건드린 영역의 기존 메모리 전부에 적용된다
- **커밋·푸시는 하지 않는다.** handoff 는 기록이지 커밋이 아니다
- **SKILL.md 에는 실행 지시만 둔다.** 매 호출마다 컨텍스트에 실리므로, 설계 이유는 아래 "설계 노트"와
  `state.sh` 주석에 둔다. 조합 해석이 필요한 판단(경로를 믿어도 되는가)은 `state.sh` 가 결론을 낸다

## 구성

```
skills/handoff/
├── SKILL.md            # 절차 · 템플릿
└── scripts/state.sh    # 기계적 상태 수집 + --verify
```

`state.sh` 는 **의존성이 없고 GNU·BSD 양쪽에서 동작한다.** 파일 수정 시각은 `stat -c`(GNU)와
`stat -f`(BSD)를 모두 시도한다.

## 설계 노트

SKILL.md 에서 뺀 "왜 이렇게 했나"를 모아 둔다. 스킬을 고칠 때 읽는다.

**스크립트 탐색이 `sort -V | tail -1` 인 이유** — 플러그인 캐시에는 구버전이 지워지지 않고 여러 버전이
함께 남는다. `find` 출력 순서는 보장되지 않아 `head -1` 은 구버전을 실행할 수 있다.
`find` 에 `cache` 한 루트만 주는 것은, 두 루트를 함께 주면 `sort -V` 가 전체 경로를 비교해
`plugins/` < `skills/` 순으로 늘 개인 스킬이 이기기 때문이다. `plugins/marketplaces/…` 는 배포 소스라 보지 않는다.
`PATH` 로 실행 중인 버전을 읽는 방법도 시도했으나, 밀려난 버전(`.orphaned_at`)까지 실려 순서에 좌우돼 더 나빴다.
남는 한계: 플러그인을 갱신하고 재시작하기 전에는 구버전 SKILL.md 가 최신 `state.sh` 를 부른다.

**존재가 아니라 내용(`HANDOFF_STATE=`)으로 확인하는 이유** — 개인 스킬 폴백 경로 `~/.claude/skills/handoff/`
는 이름만 같은 다른 handoff 스킬이 차지하고 있을 수 있다. 또 빈 문자열로 판정하면 파일이 없을 때
`bash` 가 stderr 로만 죽어 "설치 안 됨"과 "찾은 게 없음"이 구분되지 않는다.
`&& bash … || echo` 가 아니라 `if … then … else` 인 이유: `state.sh` 는 `pipefail` 이라 미추적 파일이
없거나 `--verify` 가 fail 이면 exit 1 로 끝난다. `||` 로 이으면 정상 출력 뒤에 `NOT_FOUND` 가 붙어
"설치 오류"로 오판하고 중단한다(0.2.0 까지의 결함).

**`CONFIRM_DIR` 을 스크립트가 내는 이유** — 없는 디렉토리를 만드는 것은 "여기가 맞다"는 단정이다.
슬러그가 어긋난 채 만들면 빈 메모리에 `HANDOFF_STATE=none` → 저장 모드로 들어가 진짜 인계가 방치된다.
`MEMORY_DIR_SOURCE`·`FALLBACK`·`EXISTS` 조합을 모델이 해석하게 두면 틀리므로 결론을 한 줄로 낸다.

**`HANDOFF_STATE` 가 포인터와 파일을 따로 보는 이유** — 새 세션이 자동으로 읽는 것은 `MEMORY.md` 뿐이라,
포인터가 없으면 인계는 100% 실패하고 그 실패는 발견되지 않는다. 실제로 포인터가 빠진 채 9일간 방치돼
다른 세션들이 인계를 모른 채 작업한 사고가 있었다. `--verify` 의 `VERIFY_INDEX_PTR` 이 가장 중요한 검사다.

**`--verify` 가 있는 이유** — 체크리스트는 자기보고라 지키지 않아도 티가 나지 않는다. 특히
"다음 단계 1 = 실행 명령"이 반복해서 지켜지지 않았다. 그래서 기계로 셀 수 있는 넷(포인터·섹션·
1단계 명령·미커밋 수)만 센다. 미커밋 수는 `DIRTY_COUNT` 를 그대로 옮겨야 한다 — 손으로 세면 기준이 어긋난다.

**`WORKTREE_OTHERS`** — 메인 체크아웃을 뺀 수다(0.2.0 에서 `WORKTREE_COUNT` 를 개명). −1 을 손으로
보정하면 이중 보정이 되어 워크트리 1개가 "없음"으로 적힌다.

**인덱스 예산 기능을 뺀 이유(0.3.0)** — 0.2.0 까지는 `MEMORY.md` 가 15줄을 넘으면 30일 이상 묵은
파일을 정리 후보로 제시했다. 인계와 별개인 메모리 관리 기능이라 스킬을 무겁게 했으므로 떼어냈다.
종료 시 "기존 메모리 갱신 우선" 규칙만 남겼다.

## 알려진 한계

- **동시 세션을 전제하지 않는다.** `handoff-active.md` 는 프로젝트당 하나이므로, 두 세션이
  같은 프로젝트에서 저장하면 나중 것이 앞선 것을 덮어쓴다
- **메모리 디렉토리는 세션 트랜스크립트 위치로 찾는다.** `CLAUDE_CODE_SESSION_ID` 로
  `~/.claude/projects/` 아래 트랜스크립트를 찾아 그 부모를 쓰므로 `cd` 한 뒤에도 같은 프로젝트를 본다.
  세션을 못 찾으면(세션 밖 실행·트랜스크립트 만료) 슬러그 규칙과 basename 추정으로 물러나는데,
  이때 계산한 디렉토리가 없거나 basename 으로 추정한 경로면 `CONFIRM_DIR=yes` 로 사람의 확인을 요구한다. basename 후보는 접미사가 정확히 일치하는 것이
  **유일할 때만** 채택한다 — `repo`·`app` 처럼 흔한 이름은 여러 프로젝트가 걸리기 때문이다
- **Windows Git Bash 에서는 슬러그 계산값이 늘 틀린다.** `pwd` 가 `/c/Users/x` 를 돌려줘 `-c-Users-x` 가 되지만
  실제 디렉토리는 `C--Users-x` 다. 세션 앵커가 잡히면 경로는 맞지만 `CWD_MOVED=yes` 가 잘못 켜지고,
  세션 밖에서는 늘 `CONFIRM_DIR=yes` 로 떨어진다(안전한 쪽으로 틀린다)
