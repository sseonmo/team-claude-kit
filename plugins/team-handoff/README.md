# team-handoff

`/clear` 를 건너뛰는 작업 인계 스킬.

## 문제

`/clear` 로 컨텍스트를 비우면 다음 세션은 아무것도 모른다. 그래서 매번 같은 질문이 반복된다 —
*"클리어 후에 뭐라고 말해야 하죠?"*

## 해결

**자동 로드되는 `MEMORY.md` 에 대기 포인터를 심는다.** 새 세션은 시작할 때 그 파일을 항상 읽으므로,
거기 `⏸ 진행 중 인계` 한 줄이 있으면 **스스로 인계받을 작업이 있다는 것을 안다.**

사용자가 외울 문구도 없다. 저장할 때도 재개할 때도 **`/handoff` 한 마디**면 되고,
스킬이 `handoff-active.md` 존재 여부로 모드를 판정한다.

## 사용법

```
작업 중 → /handoff        (저장 모드: 재개 지시서 작성 + 인덱스 포인터 삽입)
        → /clear          (⚠️ 이 한 번만 사용자가 직접 입력한다)
        → /handoff        (재개 모드: 읽고 → 현실과 대조 → 바로 착수)
```

`/clear` 는 CLI 동작이라 스킬이 실행할 수 없다. 그 한 번을 제외한 나머지는 전부 스킬이 한다.

## 무엇을 저장하나

`state.sh` 가 기계적 사실을 수집하고(브랜치·HEAD·미커밋·stash·worktree·메모리 인덱스 상태),
스킬은 **대화 맥락에서만 알 수 있는 것**을 채운다.

| 섹션 | 내용 |
|---|---|
| 지금 무엇을 하는 중인가 | 배경. 없으면 다음 세션이 엉뚱한 판단을 한다 |
| 다음 단계 | **실행할 명령을 그대로** 적는다. 요약이 아니라 지시서다 |
| 🚨 하지 말 것 | 되돌리기 어려운 것, 재실행하면 안 되는 명령 |
| 확인된 사실 | 실측으로 확정한 것만. 추측은 넣지 않는다 |
| ❓ 사용자 결정 대기 | 여기 항목이 있으면 재개 모드가 **그것부터 묻고** 멈춘다 |
| 상태 · 참조 | 미커밋·stash·환경 전제 · 계획서·관련 메모리 링크 |

## 설계 원칙

- **재개 모드는 보고만 하고 멈추지 않는다.** 첫 응답 3줄로 대조 결과를 알리고 바로 착수한다
- **메모리는 과거의 관찰이다.** 기록과 현재 repo 가 어긋나면 **현실을 믿고** 그 사실을 보고한다.
  이는 handoff 파일 하나가 아니라 이번 작업이 건드린 영역의 기존 메모리 전부에 적용된다
- **커밋·푸시는 하지 않는다.** handoff 는 기록이지 커밋이 아니다
- **인덱스에는 예산이 있다.** 아래 참조

## 인덱스가 무한정 자라지 않게

`MEMORY.md` 는 **매 세션 자동 로드되는 유일한 파일**이라, 여기 있는 모든 줄은 앞으로의 모든 세션이
지불하는 고정 비용이다. 그런데 handoff 사이클은 구조상 ⏸ 줄을 지우고 교훈 줄을 더하므로
**그냥 두면 항목이 순증만 한다.**

그래서 작업 종료 시 정리 단계가 이 순서를 강제한다.

1. **갱신할 기존 파일이 있는가** — 갱신이 기본, 신설이 예외
2. **이번 작업으로 틀린 게 된 메모리가 있는가** — 결론이 뒤집혔으면 갱신하거나 삭제
3. 그래도 필요하면 신설

그리고 `MEMORY_LINES` 가 **15줄**을 넘으면 저장 모드가 정리를 제안한다 —
30일 이상 손대지 않은 파일 목록을 보여주고 **유지 / 병합 / 삭제**를 묻는다.
**임의로 지우지 않는다.** 오래된 것과 틀린 것은 다르다.

> 임계 15는 조기 경보용이지 상한이 아니다. *자라는 중일 때* 잡으려고 낮게 잡은 값이고,
> 소규모 표본에서 골랐으므로 **조정해도 된다.** 제안이 잦아 성가시면 올리고, 이미 커져 있으면 내려라.
>
> `MEMORY_BYTES` 와 `MEMORY_LONGEST_CHARS` 도 함께 출력되지만 임계를 걸지 않는다 —
> 언어에 따라 3배까지 차이나서(한글 1자 = 3바이트) 누군가에게는 영영 발동하지 않기 때문이다.
> 사람이 보고 판단할 참고값이다.

## 구성

```
skills/handoff/
├── SKILL.md            # 절차 · 템플릿 · 체크리스트
└── scripts/state.sh    # 기계적 상태 수집 (판단하지 않고 사실만 찍는다)
```

`state.sh` 는 **의존성이 없고 GNU·BSD 양쪽에서 동작한다.** 파일 수정일은 `stat -c`(GNU)와
`stat -f`(BSD)를 모두 시도하고, 줄 길이는 `wc -m`(문자) 으로 센다 —
`awk length()` 는 로케일과 무관하게 바이트를 세므로 쓰지 않는다.

## 알려진 한계

- **동시 세션을 전제하지 않는다.** `handoff-active.md` 는 프로젝트당 하나이므로, 두 세션이
  같은 프로젝트에서 저장하면 나중 것이 앞선 것을 덮어쓴다
- **`~/.claude/projects/` 슬러그 규칙에 의존한다.** cwd 를 슬러그로 바꿔 메모리 디렉토리를 찾는다.
  실패하면 basename 으로 후보를 탐색하되, 접미사가 정확히 일치하는 후보가 **유일할 때만** 채택하고
  그 사실을 `MEMORY_DIR_FALLBACK=yes` 로 알린다 — `repo`·`app` 처럼 흔한 이름은 여러 프로젝트가
  걸리므로, 애매하면 집지 않는 쪽이 남의 메모리에 쓰는 것보다 낫다
